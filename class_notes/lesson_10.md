## As an OS designer, how would you rank your preferences for multithreading models

Multithreading comes from ...

- **Many to One model**: the user application has multiple threads, but the OS only has one thread to servive these threads

Benefit: Operating system has only one thread, so no overhead in processes of creating threads
Disadvantage: Threads wait in a queue to be served, could have a high wait time. If one thread invokes a blocking call, the other threads must wait, creating a bottleneck

- **One to One model**: For as many threads are in the user model, there is one to match in the kernel. Each user thread has its own kernel thread

Benefit: Practically no wait time in servicing user threads. A blocking system call will not affect other threads
Disadvantage: System can be overwhealmed by number of threads created, so there is usually a limit on how many threads can be created by an application

**Most Modern OS use One to One**

- **Many to Many Model** - There are multiple user and kernel threads, but the amount of kernel threads are less than the User threads. There is a queue, but the queue is serviced by multiple kernel threads

benefit: Better use of resources
disadvantage: small wait time. All user threads considered equal, so some threads that may be high priority still have to wait

- **Two level model** - Uses many to many, but high priority user level threads gets their own individual kernel level threads

## How does a system handle signals in a multithreading environment

Processes don't recieve messages initially, they recieve the signal for the message. In a multithreading environment, the threads live in the same space, but might have specific messsages only that thread needs, not the whole process. To make sure the message reaches the right thread, there needs to be a mechanism in place

In synchronous, the signal will be delivered to the specific thread only, generated by the specific thread
In asynchronous, the signal will be delivered to all the threads initiated by external event

T/F Async signal is always delivered to all threads, FALSE

## why do we need TLS in a multithreading environment

    TLS is thread local storage. In address space, some of the itesm will be shared between threads, but then each thread needs each own space for its own running processes. The unique parts of the address space is the TLS. We need TLS so that the threads can work independently of each other
